Every AgentMail inbox receives mail at its address as soon as it exists. This page covers the pull side of receiving: create or choose an inbox, list the threads that arrived, fetch a thread's messages, read only the new content in a reply, and download attachments or the raw email file. Push delivery (webhook and WebSocket events like `message.received`) is a separate setup and is not covered here.

All requests use `https://api.agentmail.to/v0` with `Authorization: Bearer $AGENTMAIL_API_KEY`.

## Create or choose an inbox

An inbox is addressable the moment you create it with `POST /v0/inboxes`. Every field is optional: skip `username` and one is generated randomly, skip `domain` and the address lands on `agentmail.to`. To receive on your own domain, pass a domain you have verified (or any subdomain of a verified domain with subdomains enabled, like `bot.example.com`).

<CodeGroup>

```python Python
from agentmail import AgentMail
from agentmail.inboxes import CreateInboxRequest
import os

client = AgentMail(api_key=os.getenv("AGENTMAIL_API_KEY"))

# The Python SDK wraps create parameters in a request object.
# CreateInboxRequest imports from agentmail.inboxes, not the top-level package.
inbox = client.inboxes.create(request=CreateInboxRequest(username="support"))
print(inbox.inbox_id)  # support@agentmail.to
```

```typescript TypeScript
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: process.env.AGENTMAIL_API_KEY! });

const inbox = await client.inboxes.create({ username: "support" });
console.log(inbox.inboxId); // support@agentmail.to
```

```bash CLI
agentmail inboxes create \
  --username support \
  --domain agentmail.to
```

```bash curl
curl -X POST "https://api.agentmail.to/v0/inboxes" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"username": "support"}'
```

</CodeGroup>

The returned `inbox_id` is the inbox's email address (`username@domain`). You pass it anywhere an endpoint takes `inbox_id`.

## What arrives

When someone emails your inbox, AgentMail stores the email as a message and files it into a thread, the container that groups a conversation. A fresh email starts a new thread; a reply lands in the existing one. Every inbound message is labeled `received` and `unread` on arrival, and classification can add more:

| Label             | Applied when                                                             |
| ----------------- | ------------------------------------------------------------------------ |
| `received`        | Every inbound message. System label, cannot be added or removed via API. |
| `unread`          | Every inbound message. Remove it once your agent has processed the message. |
| `spam`            | The message failed spam screening.                                       |
| `unauthenticated` | The sender's SPF, DKIM, and DMARC headers were missing entirely.         |
| `blocked`         | The sender's address or domain matches one of your block list entries.   |

Mail whose authentication headers are present but explicitly fail SPF, DKIM, or DMARC is dropped before it reaches an inbox, and there is no API to retrieve dropped mail. Missing headers are treated more leniently because some legitimate senders omit them: the message is delivered, labeled `unauthenticated`.

You can watch mail land without writing any code: the [console](https://console.agentmail.to) shows each inbox's threads as they arrive, which is the quickest way to confirm a test email actually made it in.

<Warning>
**Expected mail can look missing.** Listing endpoints hide `spam`, `unauthenticated`, `blocked`, and trashed items by default. If a sender's test email "never arrived", list with `include_spam=true` or `include_unauthenticated=true` before assuming it was dropped. Opting in also requires the API key to hold the matching label read permission (for example `label_spam_read`).

## List threads

`GET /v0/threads` lists threads across every inbox your API key can see, newest first. Scope to one inbox with `GET /v0/inboxes/{inbox_id}/threads`. Filter with `labels` to poll for work; `labels=unread` returns only conversations with unprocessed mail.

<CodeGroup>

```python Python
threads = client.threads.list(labels=["unread"])

for t in threads.threads:
    print(t.thread_id, t.subject, t.preview)
```

```typescript TypeScript
const threads = await client.threads.list({ labels: ["unread"] });

for (const t of threads.threads) {
  console.log(t.threadId, t.subject, t.preview);
}
```

```bash CLI
agentmail threads list
```

```bash curl
curl "https://api.agentmail.to/v0/threads?labels=unread" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

</CodeGroup>

The response holds `count`, an optional `next_page_token`, and `threads[]` ordered by `timestamp` descending. Each item carries `thread_id`, `senders`, `recipients`, `subject`, a text `preview` of the last message, `message_count`, and `last_message_id`. Page with `limit` and `page_token`.

You can also filter by `senders`, `recipients`, or `subject`. Filtered requests are served by search and cap `limit` at 100, and matching is by word prefix, not arbitrary substring: `subject=Verification` matches "Verification test mail", but the mid-word fragment `subject=cation test` matches nothing. Two behaviors to plan around when filtering by address: a full literal address (`agent-a@agentmail.to`) can return zero results while a prefix of its username (`senders=agent-a`) matches, so filter on the username portion; and a value made entirely of digits is parsed as a number and rejected with `400`, so keep at least one non-digit character in the filter value.

## Fetch one thread

`GET /v0/threads/{thread_id}` returns the full thread, including `messages[]` ordered by `timestamp` ascending, so the last element is the newest message. This is the call that gives you message bodies.

<CodeGroup>

```python Python
thread = client.threads.get(thread_id="thread_123")

latest = thread.messages[-1]
print(latest.subject, latest.preview)
```

```typescript TypeScript
const thread = await client.threads.get("thread_123");

const latest = thread.messages[thread.messages.length - 1];
console.log(latest.subject, latest.preview);
```

```bash CLI
agentmail threads get --thread-id thread_123
```

```bash curl
curl "https://api.agentmail.to/v0/threads/thread_123" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

</CodeGroup>

An unknown `thread_id` returns `404` with a body like `{"name": "NotFoundError", "message": "Thread not found"}`; branch on the HTTP status and the PascalCase `name` field, not the message text.

Once your agent has handled a message, remove its `unread` label with `PATCH /v0/inboxes/{inbox_id}/messages/{message_id}` (`remove_labels: ["unread"]`, optionally `add_labels: ["read"]`). Your next `labels=unread` poll then skips it, which is what keeps the agent from reprocessing the same mail.

## Read only the new content

A message body comes in up to four fields. `text` and `html` are the full body as sent, including the quoted history that clients append to replies and forwards. `extracted_text` and `extracted_html` contain just the new content, with the quoted history stripped by the Talon extraction library. For an agent responding to replies, feed it `extracted_text` so the model sees one message instead of the whole conversation again.

```python Python
for message in thread.messages:
    content = message.extracted_text or message.text
```

Fall back as shown: `extracted_text` and `extracted_html` are optional, and `text` itself can be absent when the sender transmitted an HTML-only email with no plain-text part (Gmail and Outlook do this for some forwards). `html` is the last resort.

## Download attachments and the raw message

Messages and threads list attachment metadata (`attachment_id`, `filename`, `size`, `content_type`), but not the bytes. To download, request the attachment by ID and you get back a `download_url`, a signed URL that expires at the returned `expires_at` timestamp. Fetch the URL promptly rather than storing it.

<CodeGroup>

```python Python
attachment = client.threads.get_attachment(
    thread_id="thread_123",
    attachment_id="att_456",
)
print(attachment.download_url, attachment.expires_at)
```

```typescript TypeScript
const attachment = await client.threads.getAttachment("thread_123", "att_456");
console.log(attachment.downloadUrl, attachment.expiresAt);
```

```bash CLI
agentmail threads get-attachment \
  --thread-id thread_123 \
  --attachment-id att_456
```

```bash curl
curl "https://api.agentmail.to/v0/threads/thread_123/attachments/att_456" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

</CodeGroup>

The same shape exists per message at `GET /v0/inboxes/{inbox_id}/messages/{message_id}/attachments/{attachment_id}`.

When you need the original email exactly as it crossed the wire (custom headers, MIME structure, signature verification), `GET /v0/inboxes/{inbox_id}/messages/{message_id}/raw` returns a signed `download_url` for the raw `.eml` file plus its `size` in bytes and `expires_at`.

<CodeGroup>

```python Python
raw = client.inboxes.messages.get_raw(
    inbox_id="support@agentmail.to",
    message_id="msg_789",
)
print(raw.download_url)
```

```typescript TypeScript
const raw = await client.inboxes.messages.getRaw("support@agentmail.to", "msg_789");
console.log(raw.downloadUrl);
```

```bash CLI
agentmail inboxes:messages get-raw \
  --inbox-id support@agentmail.to \
  --message-id msg_789
```

```bash curl
curl "https://api.agentmail.to/v0/inboxes/support@agentmail.to/messages/msg_789/raw" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

</CodeGroup>

**Receive email with AgentMail**

Poll an AgentMail inbox for inbound mail: list threads, fetch messages, extract new reply content, download attachments and the raw .eml. Use this for pull-based receiving; webhook/WebSocket push delivery is configured separately and is not covered here.

## Do this

```bash
export AGENTMAIL_API_KEY="your-key"
BASE="https://api.agentmail.to/v0"
AUTH="Authorization: Bearer $AGENTMAIL_API_KEY"

# 1. Create an inbox. All body fields optional; username random if omitted,
#    domain defaults to agentmail.to. Response inbox_id is the email address.
curl -X POST "$BASE/inboxes" -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"username": "support"}'

# 2. List unread threads across all visible inboxes, newest first.
curl "$BASE/threads?labels=unread" -H "$AUTH"

# 3. Fetch one thread; messages[] is ordered by timestamp ascending (last = newest).
curl "$BASE/threads/$THREAD_ID" -H "$AUTH"

# 4. Download an attachment (returns signed download_url + expires_at).
curl "$BASE/threads/$THREAD_ID/attachments/$ATTACHMENT_ID" -H "$AUTH"

# 5. Get the raw .eml (returns signed download_url + size + expires_at).
curl "$BASE/inboxes/$INBOX_ID/messages/$MESSAGE_ID/raw" -H "$AUTH"

# 6. Mark a message processed so labels=unread polls skip it.
curl -X PATCH "$BASE/inboxes/$INBOX_ID/messages/$MESSAGE_ID" \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"add_labels": ["read"], "remove_labels": ["unread"]}'
```

## SDK

Install: `pip install agentmail` (Python) or `npm install agentmail` (TypeScript). Clients: `AgentMail(api_key=...)` / `new AgentMailClient({ apiKey })`.

| Operation | Python | TypeScript |
| --- | --- | --- |
| Create inbox | `client.inboxes.create(request=CreateInboxRequest(username=..., domain=...))` | `client.inboxes.create({ username, domain })` |
| List threads (org-wide) | `client.threads.list(labels=[...], limit=..., page_token=...)` | `client.threads.list({ labels, limit, pageToken })` |
| Get thread | `client.threads.get(thread_id=...)` | `client.threads.get(threadId)` |
| Get attachment | `client.threads.get_attachment(thread_id, attachment_id)` | `client.threads.getAttachment(threadId, attachmentId)` |
| Get raw .eml | `client.inboxes.messages.get_raw(inbox_id, message_id)` | `client.inboxes.messages.getRaw(inboxId, messageId)` |
| Update labels | `client.inboxes.messages.update(inbox_id, message_id, add_labels=[...], remove_labels=[...])` | `client.inboxes.messages.update(inboxId, messageId, { addLabels, removeLabels })` |

Python `inboxes.create` takes a single keyword-only `request` parameter, not flat keyword arguments; `CreateInboxRequest` imports from `agentmail.inboxes` (`from agentmail.inboxes import CreateInboxRequest`), not the top-level `agentmail` package.

Reference: https://docs.agentmail.to/api-reference

## Facts

- Base URL is `https://api.agentmail.to/v0`; auth is `Authorization: Bearer <api key>`.
- `inbox_id` is the inbox's email address in the form `username@domain`.
- `POST /v0/inboxes` accepts optional `username`, `domain`, `display_name`, `client_id`; `domain` defaults to `agentmail.to` and custom domains must be verified (or be a subdomain of a verified domain with subdomains enabled).
- Every inbound message gets labels `received` and `unread`; classification may add `spam`, `unauthenticated`, or `blocked`.
- `spam` means the message failed spam screening; `unauthenticated` means SPF/DKIM/DMARC headers were missing; `blocked` means the sender matched a block list entry.
- Inbound mail whose authentication headers are present but fail SPF/DKIM/DMARC is dropped before delivery and cannot be retrieved.
- `GET /v0/threads` returns `{count, limit?, next_page_token?, threads[]}` ordered by `timestamp` descending; `GET /v0/inboxes/{inbox_id}/threads` is the per-inbox variant.
- `GET /v0/threads` hides `spam`, `unauthenticated`, `blocked`, and trashed threads unless `include_spam`, `include_unauthenticated`, `include_blocked`, or `include_trash` is true AND the API key holds the matching label read permission (for example `label_spam_read`).
- `GET /v0/threads` supports `senders`, `recipients`, and `subject` filters; filtered requests are served by search and cap `limit` at 100.
- Filter matching is word/prefix-based, not substring: `subject=Verification` matches "Verification test mail", but the mid-word fragment `subject=cation test` returns 0 results.
- Filtering by a full literal email address (`senders=agent-a@agentmail.to`) can return 0 results while a prefix of the username (`senders=agent-a`) matches; filter on the username portion.
- Digit-only filter values (for example `recipients=20260713`) are parsed as a number and rejected with 400; include at least one non-digit character.
- `GET /v0/threads/{thread_id}` returns the thread with `messages[]` ordered by `timestamp` ascending.
- Message body fields: `text` (plain body as sent), `html` (HTML body as sent), `extracted_text` and `extracted_html` (new content only, quoted history stripped by Talon). All four are optional; `text` is absent for HTML-only email.
- Attachment and raw-message downloads return a signed `download_url` that expires at `expires_at`; raw responses also include `size` in bytes.
- Raw .eml endpoint: `GET /v0/inboxes/{inbox_id}/messages/{message_id}/raw`.
- Per-message attachment endpoint: `GET /v0/inboxes/{inbox_id}/messages/{message_id}/attachments/{attachment_id}`.
- Mark processed: `PATCH /v0/inboxes/{inbox_id}/messages/{message_id}` with `{"remove_labels": ["unread"]}`.

## Not supported

- Python `client.inboxes.create()` does not accept flat keyword arguments like `username=` or `domain=`; pass `request=CreateInboxRequest(...)`.
- `senders`, `recipients`, and `subject` filters do not do arbitrary substring matching; mid-word fragments and full literal email addresses can return 0 results.
- No error body carries a top-level `code` field; snake_case codes (for example `invalid_type`) appear only per-entry inside a 400's `errors[]`.
- No dedicated mark-as-read endpoint; read state is the `unread` label, managed via the message PATCH endpoint.
- The `received` system label cannot be added or removed through the API.
- No API retrieves mail dropped for failed SPF/DKIM/DMARC authentication.
- Attachment metadata in thread/message objects contains no bytes and no URL; the download URL only comes from the get-attachment endpoints.
- `download_url` values expire at `expires_at`; they are not stable long-term links.

## Errors

| Name | HTTP | Body shape | Cause | Fix |
| --- | --- | --- | --- | --- |
| `NotFoundError` | 404 | `{name, message}` | Unknown `thread_id`, `inbox_id`, `message_id`, or `attachment_id`, or the item carries a label the key cannot read | Verify the ID; check label read permissions and `include_*` flags |
| `ValidationError` | 400 | `{name, errors[]}` (no top-level `message`) | Invalid request body or query parameters, including digit-only `senders`/`recipients`/`subject` filter values | Read `errors[]`; each entry has a path, a message, and a snake_case code (for example `invalid_type`) for the invalid field |

The only field present in every error body is the PascalCase `name`; branch on the HTTP status and `name`. There is no top-level `code`, and `message` is not guaranteed: 404 bodies have `{name, message}`, while 400 bodies have `{name, errors[]}` with the detail (path, message, snake_case code) per entry inside `errors[]`.

## Verify

```bash
curl "https://api.agentmail.to/v0/threads?limit=1" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

Success is HTTP 200 with a body shaped like `{"count": 1, "threads": [{"thread_id": "...", "labels": [...], "subject": "...", ...}]}`. An empty organization returns `{"count": 0, "threads": []}`.
