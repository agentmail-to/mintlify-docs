Receive email by polling threads in an AgentMail inbox. This page covers pull-based receiving. Webhook and WebSocket events such as `message.received` are configured separately.

All requests use `https://api.agentmail.to/v0` with `Authorization: Bearer $AGENTMAIL_API_KEY`.

## Create or choose an inbox

Create an inbox with `POST /v0/inboxes`. Omit `username` to generate one and `domain` to use `agentmail.to`. Custom domains must be verified; enabled subdomains of a verified domain also work.

<CodeGroup>

```bash CLI
agentmail inboxes create \
  --username support \
  --domain agentmail.to
```

```bash curl
curl -X POST "https://api.agentmail.to/v0/inboxes" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"username": "support"}'
```

```typescript TypeScript
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: process.env.AGENTMAIL_API_KEY! });
const inbox = await client.inboxes.create({ username: "support" });

console.log(inbox.inboxId); // support@agentmail.to
```

```python Python
import os
from agentmail import AgentMail
from agentmail.inboxes import CreateInboxRequest

client = AgentMail(api_key=os.getenv("AGENTMAIL_API_KEY"))
inbox = client.inboxes.create(
    request=CreateInboxRequest(username="support")
)

print(inbox.inbox_id)  # support@agentmail.to
```

</CodeGroup>

Python wraps create fields in `CreateInboxRequest`, imported from `agentmail.inboxes`. The returned `inbox_id` is the email address used by endpoints that take `inbox_id`.

## Understand inbound messages

AgentMail stores each email as a message in a thread. A new email starts a thread; replies join it. Inbound messages get `received` and `unread`; classification can add labels:

| Label | Applied when |
| --- | --- |
| `received` | Every inbound message. This system label cannot be changed through the API. |
| `unread` | Every inbound message. Remove it after processing. |
| `spam` | The message failed spam screening. |
| `unauthenticated` | SPF, DKIM, and DMARC headers were all missing. |
| `blocked` | The sender address or domain matches a block-list entry. |

Messages with present but failing SPF, DKIM, or DMARC are dropped before delivery and cannot be retrieved. Messages with missing authentication headers are delivered with `unauthenticated`.

<Warning>
**Expected email can look missing.** Thread listings hide `spam`, `unauthenticated`, `blocked`, and trashed items by default. Use the relevant `include_*` flag, such as `include_spam=true`, and an API key with the matching label-read permission, such as `label_spam_read`.
</Warning>

## List unread threads

`GET /v0/threads` lists threads across inboxes visible to your API key, newest first. Use `GET /v0/inboxes/{inbox_id}/threads` for one inbox. Poll with `labels=unread` to find unprocessed conversations.

<CodeGroup>

```bash CLI
agentmail threads list
```

```bash curl
curl "https://api.agentmail.to/v0/threads?labels=unread" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

```typescript TypeScript
const threads = await client.threads.list({ labels: ["unread"] });

for (const thread of threads.threads) {
  console.log(thread.threadId, thread.subject, thread.preview);
}
```

```python Python
threads = client.threads.list(labels=["unread"])

for thread in threads.threads:
    print(thread.thread_id, thread.subject, thread.preview)
```

</CodeGroup>

The response has `count`, optional `next_page_token`, and `threads[]` ordered by descending `timestamp`. Each item includes `thread_id`, `senders`, `recipients`, `subject`, the last-message `preview`, `message_count`, and `last_message_id`. Page with `limit` and `page_token`.

Search filters `senders`, `recipients`, and `subject` cap `limit` at 100. They match word prefixes, not arbitrary substrings: `subject=Verification` matches "Verification test mail" but `subject=cation test` does not. A full email address can return no results while its username prefix matches, so filter on the username portion. Digit-only values are parsed as numbers and return `400`; include a non-digit character.

## Fetch and mark a thread processed

`GET /v0/threads/{thread_id}` returns `messages[]` in ascending `timestamp` order, so the last item is newest.

<CodeGroup>

```bash CLI
agentmail threads get --thread-id thread_123
```

```bash curl
curl "https://api.agentmail.to/v0/threads/thread_123" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

```typescript TypeScript
const thread = await client.threads.get("thread_123");
const latest = thread.messages[thread.messages.length - 1];

console.log(latest.subject, latest.preview);
```

```python Python
thread = client.threads.get(thread_id="thread_123")
latest = thread.messages[-1]

print(latest.subject, latest.preview)
```

</CodeGroup>

An unknown `thread_id` returns `404` with `{"name": "NotFoundError", "message": "Thread not found"}`. Branch on HTTP status and the PascalCase `name`, not the message.

After processing a message, remove `unread` with `PATCH /v0/inboxes/{inbox_id}/messages/{message_id}` using `remove_labels: ["unread"]`. You can also add `read`. The next unread poll skips that message.

## Read only the new reply content

`text` and `html` contain the full sent body, including quoted history. `extracted_text` and `extracted_html` contain new content with quoted history stripped by Talon. Use `extracted_text` for a reply, then fall back to `text`; `text` can be absent for HTML-only email, so use `html` last.

<CodeGroup>

```bash CLI
agentmail threads get --thread-id thread_123 \
  | jq -r '.messages[-1].extracted_text // .messages[-1].text // .messages[-1].html'
```

```bash curl
curl "https://api.agentmail.to/v0/threads/thread_123" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  | jq -r '.messages[-1].extracted_text // .messages[-1].text // .messages[-1].html'
```

```typescript TypeScript
const latest = thread.messages[thread.messages.length - 1];
const content = latest.extractedText ?? latest.text ?? latest.html;
```

```python Python
latest = thread.messages[-1]
content = latest.extracted_text or latest.text or latest.html
```

</CodeGroup>

## Download attachments and raw email

Thread and message objects contain attachment metadata (`attachment_id`, `filename`, `size`, `content_type`), not bytes. Get an attachment to receive a signed `download_url` and `expires_at`; fetch it before it expires.

<CodeGroup>

```bash CLI
agentmail threads get-attachment \
  --thread-id thread_123 \
  --attachment-id att_456
```

```bash curl
curl "https://api.agentmail.to/v0/threads/thread_123/attachments/att_456" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

```typescript TypeScript
const attachment = await client.threads.getAttachment("thread_123", "att_456");
console.log(attachment.downloadUrl, attachment.expiresAt);
```

```python Python
attachment = client.threads.get_attachment(
    thread_id="thread_123",
    attachment_id="att_456",
)
print(attachment.download_url, attachment.expires_at)
```

</CodeGroup>

The per-message endpoint is `GET /v0/inboxes/{inbox_id}/messages/{message_id}/attachments/{attachment_id}`.

For original headers, MIME structure, or signature verification, use `GET /v0/inboxes/{inbox_id}/messages/{message_id}/raw`. It returns a signed `.eml` `download_url`, `size`, and `expires_at`.

<CodeGroup>

```bash CLI
agentmail inboxes:messages get-raw \
  --inbox-id support@agentmail.to \
  --message-id msg_789
```

```bash curl
curl "https://api.agentmail.to/v0/inboxes/support@agentmail.to/messages/msg_789/raw" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

```typescript TypeScript
const raw = await client.inboxes.messages.getRaw("support@agentmail.to", "msg_789");
console.log(raw.downloadUrl);
```

```python Python
raw = client.inboxes.messages.get_raw(
    inbox_id="support@agentmail.to",
    message_id="msg_789",
)
print(raw.download_url)
```

</CodeGroup>

# Receive email with AgentMail

Poll an AgentMail inbox for inbound threads, reply content, attachments, and raw `.eml` files. Webhook and WebSocket receiving are separate.

## Do this

```bash
export AGENTMAIL_API_KEY="your-key"
BASE="https://api.agentmail.to/v0"
AUTH="Authorization: Bearer $AGENTMAIL_API_KEY"

agentmail inboxes create --username support --domain agentmail.to
agentmail threads list
agentmail threads get --thread-id "$THREAD_ID"
agentmail threads get-attachment \
  --thread-id "$THREAD_ID" \
  --attachment-id "$ATTACHMENT_ID"
agentmail inboxes:messages get-raw \
  --inbox-id "$INBOX_ID" \
  --message-id "$MESSAGE_ID"

curl -X PATCH "$BASE/inboxes/$INBOX_ID/messages/$MESSAGE_ID" \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"add_labels":["read"],"remove_labels":["unread"]}'
```

## SDK

Install: `npm install agentmail` (TypeScript) or `pip install agentmail` (Python). Clients: `new AgentMailClient({ apiKey })` / `AgentMail(api_key=...)`.

| Operation | TypeScript | Python |
| --- | --- | --- |
| Create inbox | `client.inboxes.create({ username, domain })` | `client.inboxes.create(request=CreateInboxRequest(username=..., domain=...))` |
| List threads | `client.threads.list({ labels, limit, pageToken })` | `client.threads.list(labels=[...], limit=..., page_token=...)` |
| Get thread | `client.threads.get(threadId)` | `client.threads.get(thread_id=...)` |
| Get attachment | `client.threads.getAttachment(threadId, attachmentId)` | `client.threads.get_attachment(thread_id, attachment_id)` |
| Get raw `.eml` | `client.inboxes.messages.getRaw(inboxId, messageId)` | `client.inboxes.messages.get_raw(inbox_id, message_id)` |
| Update labels | `client.inboxes.messages.update(inboxId, messageId, { addLabels, removeLabels })` | `client.inboxes.messages.update(inbox_id, message_id, add_labels=[...], remove_labels=[...])` |

Python requires `request=CreateInboxRequest(...)` for `inboxes.create`; import `CreateInboxRequest` from `agentmail.inboxes`.

Reference: https://docs.agentmail.to/api-reference

## Facts

- Base URL: `https://api.agentmail.to/v0`. Auth: `Authorization: Bearer <api key>`.
- `inbox_id` is `username@domain`.
- Inbox creation accepts optional `username`, `domain`, `display_name`, and `client_id`. The default domain is `agentmail.to`; custom domains must be verified, or be an enabled subdomain of one.
- Inbound messages receive `received` and `unread`; classification can add `spam`, `unauthenticated`, or `blocked`.
- Present but failing SPF, DKIM, or DMARC causes the email to be dropped. Missing headers deliver the email with `unauthenticated`.
- `GET /v0/threads` returns `{count, limit?, next_page_token?, threads[]}` in descending `timestamp` order. `GET /v0/inboxes/{inbox_id}/threads` scopes to one inbox.
- Listings hide spam, unauthenticated, blocked, and trashed threads by default. Use the relevant `include_*` flag and matching label-read permission.
- Thread filters `senders`, `recipients`, and `subject` use word-prefix matching, cap `limit` at 100, and do not match arbitrary substrings. Filter addresses by username prefix; digit-only values return `400`.
- `GET /v0/threads/{thread_id}` returns `messages[]` in ascending `timestamp` order.
- `text` and `html` are full bodies. Optional `extracted_text` and `extracted_html` omit quoted history. `text` can be absent for HTML-only email.
- Attachment and raw-email endpoints return a signed `download_url` and `expires_at`; raw email also returns `size`.
- Attachment endpoint: `GET /v0/inboxes/{inbox_id}/messages/{message_id}/attachments/{attachment_id}`. Raw endpoint: `GET /v0/inboxes/{inbox_id}/messages/{message_id}/raw`.
- Mark processed with `PATCH /v0/inboxes/{inbox_id}/messages/{message_id}` and `{"remove_labels":["unread"]}`.

## Not supported

- Python `client.inboxes.create()` does not accept flat `username=` or `domain=` arguments.
- Filters do not support arbitrary substrings; full literal addresses can return no results.
- Error bodies have no top-level `code`. Field-level snake_case codes occur only in a 400 response's `errors[]`.
- `received` cannot be changed through the API.
- Dropped authentication failures cannot be retrieved.
- Attachment metadata has no bytes or download URL. Signed URLs are temporary.

## Errors

| Name | HTTP | Body | Fix |
| --- | --- | --- | --- |
| `NotFoundError` | 404 | `{name, message}` | Verify the ID, label-read permissions, and `include_*` flags. |
| `ValidationError` | 400 | `{name, errors[]}` | Read each entry's path, message, and snake_case code. |

Branch on HTTP status and PascalCase `name`. Only `name` is present in every error body: 404 has `message`; 400 detail is in `errors[]`.

## Verify

```bash
agentmail threads list
```

Success returns threads visible to the API key. An empty organization returns `count: 0` and an empty `threads` list.
