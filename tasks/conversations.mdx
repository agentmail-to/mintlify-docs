<Human>

Every message belongs to a thread. Replies attach through `in_reply_to`, so you can fetch, label, and search a conversation as one resource.

All requests use `https://api.agentmail.to/v0` with `Authorization: Bearer $AGENTMAIL_API_KEY`.

## Fetch a thread

`GET /threads/{thread_id}` returns thread metadata and all messages. Messages are ordered by `timestamp` ascending: `messages[0]` is oldest and the final element is newest. `last_message_id` identifies the newest message without reading `messages`.

<CodeGroup>

```bash CLI
agentmail threads get \
  --thread-id "$THREAD_ID"
```

```bash curl
curl "https://api.agentmail.to/v0/threads/$THREAD_ID" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

```typescript TypeScript
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: process.env.AGENTMAIL_API_KEY });
const thread = await client.threads.get(threadId);

console.log(thread.subject);
console.log(thread.messages.at(-1)?.text); // newest message
```

```python Python
import os
from agentmail import AgentMail

client = AgentMail(api_key=os.environ["AGENTMAIL_API_KEY"])
thread = client.threads.get(thread_id=thread_id)

print(thread.subject)
print(thread.messages[-1].text)  # newest message
```

</CodeGroup>

| Field | Meaning |
| --- | --- |
| `labels` | Union of labels on all thread messages |
| `senders`, `recipients` | Every address in the thread, as `username@domain.com` or `Display Name <username@domain.com>` |
| `subject`, `preview` | Subject and a text preview of the last message |
| `timestamp` | Last sent or received message timestamp |
| `received_timestamp`, `sent_timestamp` | Last received and last sent timestamps |
| `message_count`, `size` | Message count and thread size in bytes |
| `last_message_id` | Newest message ID |

`GET /threads` lists threads newest-first with `count`, optional `next_page_token`, and a `labels` filter. Its scope comes from the API key. Use `GET /inboxes/{inbox_id}/threads` or `GET /pods/{pod_id}/threads` to set scope explicitly. `senders`, `recipients`, and `subject` filters are served by search and limit results to 100.

## Track agent state with labels

System labels are set by the delivery pipeline and cannot be changed through the API: `received`, `sent`, `bounced`, `complained`, `delayed`, `delivered`, `rejected`, `opened`, and `scheduled`. Use custom labels for agent state, such as `triaged` after classification or `escalated` for human handoff, then filter list endpoints by `labels`.

`PATCH /threads/{thread_id}` accepts `add_labels` and `remove_labels` and applies the change to every message in the thread. List threads with `labels=unread`, then remove `unread` and add your state label in one request.

<CodeGroup>

```bash curl
curl -X PATCH "https://api.agentmail.to/v0/threads/$THREAD_ID" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"add_labels": ["triaged"], "remove_labels": ["unread"]}'
```

```typescript TypeScript
const updated = await client.threads.update(threadId, {
  addLabels: ["triaged"],
  removeLabels: ["unread"],
});

console.log(updated.labels);
```

```python Python
updated = client.threads.update(
    thread_id=thread_id,
    add_labels=["triaged"],
    remove_labels=["unread"],
)

print(updated.labels)
```

</CodeGroup>

- Labels are trimmed and lowercased on write; each is limited to 256 characters.
- A system label in `add_labels` or `remove_labels` returns 400 `ValidationError`.
- When a label is in both fields, removal wins.
- Updates return 422 `UnprocessableError` for threads with 100 or more messages. Update individual messages with `PATCH /inboxes/{inbox_id}/messages/{message_id}`, or up to 50 at once with `POST /inboxes/{inbox_id}/messages/batch-update`.

## Search conversations

Thread search is relevance-ranked full-text search. It matches senders, recipients, and subject as substrings, and message bodies as tokenized full text.

| Scope | Endpoint |
| --- | --- |
| Organization | `GET /threads/search` |
| Pod | `GET /pods/{pod_id}/threads/search` |
| Inbox | `GET /inboxes/{inbox_id}/threads/search` |

<CodeGroup>

```bash curl
curl -G "https://api.agentmail.to/v0/threads/search" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  --data-urlencode "q=invoice 1042"
```

```typescript TypeScript
const results = await client.threads.search({ q: "invoice 1042" });

for (const thread of results.threads) {
  console.log(thread.thread_id, thread.subject, thread.highlights);
}
```

```python Python
results = client.threads.search(q="invoice 1042")

for thread in results.threads:
    print(thread.thread_id, thread.subject, thread.highlights)
```

</CodeGroup>

Results are relevance-ranked, not recency-ranked. `highlights` may contain matched fragments for `from`, `recipients`, `subject`, and `text`, with terms wrapped in `**`; a key appears only when that field matched. `limit` defaults to 50 and cannot exceed 100. Use `page_token` to page and `before` or `after` to bound time. Search always excludes spam, trash, blocked, and unauthenticated threads.

`GET /inboxes/{inbox_id}/messages/search` searches individual messages at inbox scope only. There is no organization- or pod-scope message search. For content across inboxes, search organization-scope threads, then fetch their messages.

Use list filters for sender or subject results ordered by recency. Use search for body content or relevance ranking.

## Handle concurrent updates

Simultaneous replies or a label update racing an inbound message can produce HTTP 409 `RaceConditionError`. Retry the request. Label updates converge on retry because they add and remove labels rather than replace the label set. If the retry depends on the current labels, fetch the thread first.

# Fetch, label, and search AgentMail conversation threads

Read a full email thread, track agent state with custom labels, and search existing conversations.

## Do this

```bash
export AGENTMAIL_API_KEY="..."
BASE="https://api.agentmail.to/v0"

# Get a thread with the CLI
agentmail threads get \
  --thread-id "$THREAD_ID"

# Update labels on every message in the thread
curl -X PATCH "$BASE/threads/$THREAD_ID" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"add_labels": ["triaged"], "remove_labels": ["unread"]}'

# Search threads across the organization
curl -G "$BASE/threads/search" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  --data-urlencode "q=invoice 1042"
```

## Facts

- Base URL: `https://api.agentmail.to/v0`; auth header `Authorization: Bearer $AGENTMAIL_API_KEY`.
- `GET /v0/threads/{thread_id}` returns thread metadata plus `messages[]` ordered by `timestamp` ascending (oldest first).
- Thread metadata fields: `inbox_id`, `thread_id`, `labels`, `timestamp`, `received_timestamp?`, `sent_timestamp?`, `senders`, `recipients`, `subject?`, `preview?`, `attachments?`, `last_message_id`, `message_count`, `size`, `updated_at`, `created_at`.
- A thread's `labels` is the union of its messages' labels.
- `GET /v0/threads` lists threads by descending `timestamp`; response is `{count, limit?, next_page_token?, threads[]}`. Filter with `labels`, `before`, `after`; `senders`/`recipients`/`subject` filters use search and cap `limit` at 100.
- `/v0/threads...` resolves scope from the API key; `/v0/inboxes/{inbox_id}/threads...` and `/v0/pods/{pod_id}/threads...` set it explicitly.
- System labels are set by the platform and rejected from `add_labels`/`remove_labels` with 400: `received`, `sent`, `bounced`, `complained`, `delayed`, `delivered`, `rejected`, `opened`, `scheduled`.
- Custom labels are trimmed and lowercased on write; maximum 256 characters per label.
- `PATCH /v0/threads/{thread_id}` body `{add_labels?, remove_labels?}` applies to every message in the thread. `remove_labels` wins on duplicates; response is `{thread_id, labels}`.
- `PATCH /v0/threads/{thread_id}` returns 422 `UnprocessableError` when a thread has 100 or more messages. Use `PATCH /v0/inboxes/{inbox_id}/messages/{message_id}` or `POST /v0/inboxes/{inbox_id}/messages/batch-update` instead. Batch update accepts up to 50 IDs and is atomic.
- Thread search: `GET /v0/threads/search` (org), `GET /v0/pods/{pod_id}/threads/search`, `GET /v0/inboxes/{inbox_id}/threads/search`; parameters: `q`, `limit`, `page_token`, `before`, `after`.
- Message search is inbox-only: `GET /v0/inboxes/{inbox_id}/messages/search`.
- Search matches `q` against senders, recipients, and subject as substrings, and message bodies as tokenized full text. Results are relevance-ranked.
- Search `limit` defaults to 50, maximum 100. `page_token` pages within the first 10,000 results.
- Search results may include `highlights` with matched fragments in `from`, `recipients`, `subject`, and `text`, with terms wrapped in `**`. A key appears only when that field matched.
- Search excludes spam, trash, blocked, and unauthenticated email.
- Search and thread reads require `message_read`; label updates require `message_update`.
- Concurrent thread writes fail with 409 `RaceConditionError`; retry the request.

## Not supported

- No organization- or pod-scope message search: `GET /v0/messages/search` and `GET /v0/pods/{pod_id}/messages/search` do not exist. Search organization-scope threads instead.
- System labels cannot be added or removed through the API.
- Search has no `include_spam`/`include_blocked`/`include_unauthenticated`/`include_trash` parameters. The exclusions are unconditional; list endpoints accept those parameters.
- No label rename. Remove the old label and add the new one.
- Search cannot sort by recency. Use filtered list endpoints for recency ordering.

## Errors

| Error name | HTTP | Cause | Fix |
| --- | --- | --- | --- |
| `ValidationError` | 400 | System label in `add_labels`/`remove_labels`, or `limit` > 100 on search | Use custom labels only; keep `limit <= 100` |
| `ForbiddenError` | 403 | API key lacks `message_read` (reads/search) or `message_update` (label edits) | Use a key with the required permission |
| `NotFoundError` | 404 | Thread ID does not exist or is outside the key's scope | Check the ID and the key's inbox/pod/org scope |
| `RaceConditionError` | 409 | A concurrent thread write raced this request | Retry the request |
| `UnprocessableError` | 422 | `PATCH /v0/threads/{thread_id}` on a thread with 100+ messages | Update messages individually or with batch update |

## Verify

```bash
curl -G "https://api.agentmail.to/v0/threads" \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  --data-urlencode "limit=1"
```

Success returns HTTP 200 with `{"count": ..., "threads": [...]}`. A thread confirms scope and `message_read` permission.
