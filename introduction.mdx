AgentMail is email built for AI agents instead of people. This page explains what it does, why an agent needs an inbox of its own, and how it differs from the email tools you already use, so you can decide whether it fits and pick a surface to start with.

## What AgentMail is

AgentMail gives AI agents programmable email inboxes. You create an inbox, receive mail sent to it, trigger workflows on incoming messages, and send replies, all through one API. An agent gets a real address it can hand out, watch, and act on without a human sitting in a mail client.

## Why agents need email

Email is the account layer of the internet. Signing up for a service, confirming an address, resetting a password, and receiving receipts or notifications all run through an inbox, so an agent that does any of these needs an address mail can reach it at.

That address should belong to the agent. Borrowing a human's inbox works until the agent has to act unattended or you run more agents than one mailbox can serve. With its own inbox, an agent registers for the tools it needs, receives verification codes and finishes those flows on its own, and holds ongoing correspondence with services and people.

## How AgentMail differs from email tools you know

The email tools you already know move mail on behalf of humans; AgentMail gives an agent an inbox of its own to send from and receive into.

| Tool | Who it serves | What it moves |
| --- | --- | --- |
| AgentMail | AI agents | An agent's own inbox: send and receive, with workflows on incoming mail |
| SendGrid / Resend | Your application | Outbound transactional email your app generates |
| Mailchimp | Marketers | Outbound marketing broadcasts to a subscriber list |
| Gmail API | A human user | Programmatic access to that person's existing mailbox |

## Five ways to use AgentMail

Reach AgentMail through whichever surface fits how you work. All five talk to the same API.

<CardGroup cols={2}>
  <Card title="CLI" icon="terminal">
    The fastest way to try calls from a terminal or script one-off checks, before you write any application code.
  </Card>
  <Card title="MCP" icon="plug">
    Give an MCP-capable agent or assistant direct control of inboxes as tools, without writing glue code.
  </Card>
  <Card title="Console" icon="browser">
    Inspect inboxes and messages in the browser when you want to see what your code did rather than query it.
  </Card>
  <Card title="SDK (Python, TypeScript)" icon="code">
    Build AgentMail into an application with typed calls instead of hand-rolled requests.
  </Card>
</CardGroup>

The fifth surface is raw HTTP: every operation is available directly over the API, so pick it when you work in a language without an SDK or want no dependency at all.
