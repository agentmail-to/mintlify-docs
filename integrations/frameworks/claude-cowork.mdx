[Claude Cowork](https://claude.com/docs/cowork/overview) is Anthropic's agentic workspace in the Claude Desktop app. It takes an outcome you describe and works through the steps on its own. The official AgentMail plugin gives it an email inbox of its own, authenticated by an AgentMail sign-in instead of an API key. The plugin connects AgentMail's hosted email tools and installs skills that make Cowork draft before it sends and treat inbound mail as untrusted data. Follow the steps and you will watch Cowork send email from its own `@agentmail.to` address, then triage the reply.

## 0. Set up Claude and AgentMail

You need two things:

- Claude Desktop with the Cowork tab. Plugins are available on the paid Claude plans: Pro, Max, Team, and Enterprise.
- An AgentMail account. [Sign up at the Console](https://console.agentmail.to) if you are new. The sign-in in step 2 uses this account.

There is no environment variable or key to set. Cowork opens the AgentMail sign-in in your browser when it first uses an email tool.

## 1. Install the AgentMail plugin

Open **Customize** in the Claude Desktop sidebar and go to **Plugins**. Choose **Add > Add marketplace**, enter `https://github.com/agentmail-to/agentmail-plugins`, and click **Sync**.

<Frame caption="The Add marketplace dialog with the AgentMail plugins repository.">
  <img src="/images/integrations/cowork-add-marketplace.png" alt="Claude Desktop's Add marketplace dialog with the agentmail-to/agentmail-plugins repository URL" />
</Frame>

The plugin directory opens on the new `agentmail` source. Select **+** on the **AgentMail** card, and a toast confirms the install.

<Frame caption="The AgentMail plugin installed from the synced marketplace.">
  <img src="/images/integrations/cowork-install.png" alt="Claude Desktop's plugin directory showing the AgentMail plugin with the installed confirmation" />
</Frame>

The plugin bundles its connection to AgentMail's hosted email tools, so this install is the whole setup. It also installs these skills:

| Skill | What it does |
| --- | --- |
| `send-email` | Drafts, sends, replies, and forwards. Anything Cowork wrote itself is shown to you before it is sent. |
| `check-email` | Reads, searches, summarizes, and triages your inboxes. |
| `manage-inboxes` | Creates, inspects, updates, and deletes inboxes. Deleting requires your confirmation of the exact address. |
| `agent-email-patterns` | Architecture and security patterns for agents that communicate over email. |
| `agentmail` | TypeScript and Python SDK guidance for AgentMail coding tasks. |
| `agentmail-cli` | AgentMail workflows from the command line. |
| `agentmail-mcp` | Setup and troubleshooting for the hosted tool connection. |
| `agentmail-toolkit` | AgentMail tools in agent frameworks such as LangChain and the Vercel AI SDK. |

The first three run your email tasks. The rest guide coding work you hand to Cowork, for example building an email-driven agent of your own. Cowork applies a skill when a task matches it, and typing `/` in the input lists them.

To connect the email tools without the skills, add a custom connector for `https://mcp.agentmail.to/mcp` instead. [MCP and Skills](/integrations/mcp-and-skills) covers that setup and the full tool catalog.

## 2. Sign in and list your inboxes

Start a new Cowork session and give it its first email task:

```text Prompt
List my AgentMail inboxes
```

The first AgentMail tool call opens the AgentMail sign-in in your browser. Sign in, approve the access it lists, and the page ends on "Authentication Successful". Cowork then calls the `list_inboxes` tool and answers with your inbox addresses. An empty list is fine. You create an inbox in the next step.

<Frame caption="The first email task: the browser sign-in, then the inbox list.">
  <img src="/images/integrations/cowork-sign-in.png" alt="A Cowork session running the AgentMail sign-in and then listing two inboxes in a table" />
</Frame>

Cowork loads plugins when a session starts. If the AgentMail tools are missing, the session predates the install. Start a new session and ask again.

## 3. Test sending an email

Ask Cowork to create an inbox and send a test email to an account you already check, whether that is Gmail, Outlook, or another client:

```text Prompt
Create an AgentMail inbox for me, then send an email from it to
you@example.com with the subject "Hello from Cowork" and a one-line
introduction. Let me know the inbox address once it is sent.
```

Cowork writes the introduction itself, so expect a preview: the complete email, with a request to confirm before it sends. Approve it, and the email arrives in that account a moment or two later, from a newly created `@agentmail.to` address such as `faircost773@agentmail.to`. Cowork reports the address and the send's message and thread IDs. Save the address. You will email it in the next step.

<Frame caption="The send test: a fresh inbox, then the email delivered with its thread id.">
  <img src="/images/integrations/cowork-send.png" alt="A Cowork session creating an inbox and reporting the sent email with its thread id" />
</Frame>

Asking Cowork to "write", "compose", or "prepare" an email creates a draft instead of sending one.

This prompt leaves the username to AgentMail, which generates an available one.

<Accordion title="Troubleshooting">

- **`403` when you ask for a specific name.** A taken username fails with a `403` that lists up to three available alternatives in `suggestions`, so Cowork can retry with one you approve.

</Accordion>

## 4. Test receiving and triaging email

From your own account, reply to the email you just received. Then ask Cowork to triage:

```text Prompt
Check my AgentMail inbox for new mail and summarize anything that needs a reply.
```

Cowork searches the inbox, reads the full conversation, and answers with a summary that names your reply. Searches skip spam and trash, so what comes back is mail worth acting on.

Ask it to answer the reply and the send rules from step 3 apply again: Cowork writes the reply, shows it to you, and sends after you confirm. The reply arrives in the same email thread as the original.

These skills treat email content as untrusted data. When a request arrives inside an inbound email, Cowork turns it into a proposal and waits for your approval. [Agent safety](/advanced/safety) explains this model and how to apply it to agents you build.

# Give Claude Cowork an email inbox with the AgentMail plugin

The official AgentMail plugin connects Claude Cowork to AgentMail's hosted email tools and installs skills that make it draft before sending and treat inbound mail as untrusted data. Use it when Cowork should send, receive, and triage email from its own `@agentmail.to` address, authenticated by an AgentMail sign-in instead of an API key.

## Do this

1. Get Claude Desktop with the Cowork tab on a paid Claude plan (Pro, Max, Team, or Enterprise) and an AgentMail account from `https://console.agentmail.to`. No environment variable or key is needed.
2. Open the Cowork tab in Claude Desktop, open Customize in the sidebar, and go to the Plugins tab.
3. Under Personal plugins, select the plus button, choose Add marketplace, then Add from a repository, and enter `https://github.com/agentmail-to/agentmail-plugins`.
4. Once the marketplace syncs, select Browse plugins and install AgentMail.
5. Start a new Cowork session and prompt `List my AgentMail inboxes`. The first AgentMail tool call opens the AgentMail sign-in in the browser. Sign in, and pick an organization if you belong to more than one. An empty list is fine.
6. Ask Cowork to create an inbox and send a test email:

```text
Create an AgentMail inbox for me, then send an email from it to
you@example.com with the subject "Hello from Cowork" and a one-line
introduction. Let me know the inbox address once it is sent.
```

7. Cowork shows the complete email and asks for confirmation before sending anything it wrote itself. Approve it, then save the reported address.
8. Reply to the test email from your own account, then prompt `Check my AgentMail inbox for new mail and summarize anything that needs a reply.` Ask Cowork to answer the reply and it previews, waits for confirmation, and sends in the same thread.

## Facts

- Marketplace repository: `https://github.com/agentmail-to/agentmail-plugins`, added under Personal plugins via Add marketplace, then Add from a repository.
- Authentication is an AgentMail browser sign-in on the first email tool call. No API key, no environment variable.
- Plugins are available on the paid Claude plans: Pro, Max, Team, and Enterprise.
- The plugin bundles its connection to AgentMail's hosted email tools and installs 8 skills. Cowork applies a skill when a task matches it, and typing `/` in the input lists them.
- Skills that run email tasks: `send-email` (drafts, sends, replies, and forwards, with anything Cowork wrote shown for confirmation before it is sent), `check-email` (reads, searches, summarizes, and triages inboxes), `manage-inboxes` (creates, inspects, updates, and deletes inboxes).
- Skills that guide coding work: `agent-email-patterns` (architecture and security patterns for agents that communicate over email), `agentmail` (TypeScript and Python SDK guidance), `agentmail-cli` (command line workflows), `agentmail-mcp` (hosted tool connection setup and troubleshooting), `agentmail-toolkit` (AgentMail tools in frameworks such as LangChain and the Vercel AI SDK).
- Asking Cowork to "write", "compose", or "prepare" an email creates a draft instead of sending one.
- Inbox searches skip spam and trash.
- The reply Cowork sends arrives in the same email thread as the original. Cowork reports the send's message and thread IDs.
- Creating an inbox without a requested name lets AgentMail generate an available username. A taken username fails with `403` listing up to 3 available alternatives in `suggestions`, so Cowork can retry with one you approve.
- The skills treat email content as untrusted data. A request that arrives inside an inbound email becomes a proposal that waits for approval.
- Cowork loads plugins when a session starts.
- To connect the email tools without the skills, add a custom connector for `https://mcp.agentmail.to/mcp` instead. Setup and the full tool catalog: [MCP and Skills](/integrations/mcp-and-skills).

## Not supported

- Cowork does not send email it wrote itself without showing it for confirmation first.
- A session started before the install has no AgentMail tools. Start a new session and ask again.
- Deleting an inbox does not proceed without confirmation of the exact address.
- A request embedded in inbound email is not executed directly. It becomes a proposal awaiting approval.
- There is no API key or environment variable to set for the plugin. The sign-in happens in the browser on first use.

## Errors

| Error | Status | Cause | Fix |
| --- | --- | --- | --- |
| `resource_taken` | 403 | The requested inbox username belongs to another organization. | Retry with one of the up to 3 alternatives in `suggestions`. |
| `already_exists` | 403 | An inbox with the requested username already exists in the organization. | Retry with a username from `suggestions`, or use the existing inbox. |

## Verify

Prompt `List my AgentMail inboxes` in a new Cowork session. Success is the browser sign-in completing and Cowork calling the `list_inboxes` tool, then answering with the inbox addresses. An empty list is a valid answer.
